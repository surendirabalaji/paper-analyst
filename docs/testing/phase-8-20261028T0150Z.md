## 4. Defects

**P8-D1 (Minor, Frontend 15%: double-submit control).** Pressing Enter in the textarea while a turn is running starts a second, concurrent request.

- **Cause:** the `keydown` handler calls `$("ask").requestSubmit()`. `requestSubmit()` fires `submit` even though `#send` is disabled, and the submit handler does not check for an in-flight turn.
- **Effect:**
  - Two turns stream at once, each a paid request.
  - When the first turn finishes, its `finally` re-enables Ask while the second is still running.
- **Evidence:** M7b (`calls_after_enter: 2`, `turns_running_concurrently: 2`).
- **Not affected:** the turns stay isolated (M3/M7c).
- **Fix direction:** return early in the submit handler while a turn is in flight.

**P8-D2 (Minor, Frontend 15%: routing visibility).**

- **Trigger:** a question containing a long unbroken token, such as a pasted URL. The over-length 422 case triggers it too.
- **Effect:** the Routing table becomes wider than the panel, and the Provider · model, Why and Result columns move off-screen for every later turn on that page. They can only be reached by scrolling sideways.
- **Cause:** `tr.turn-head td` (colSpan 5, holding the full question) has no `overflow-wrap`.
- **Evidence:** M12 (column right edges at 1,615 and 1,827 px against a 1,484 px panel), `mock/m12_long_url_routing.png` and deployed `deployed/d1_tab_a_routing.png`. The second shows only the Turn and Agent columns after the 2,500-character turn.
- **Fix direction:** wrap or truncate the turn-head cell (for example `overflow-wrap: anywhere`, with the full text in a `title`).

## 5. Non-blocking notes

- **N1 (polish):** light-mode contrast is just under 4.5:1 for 11 px `.badge.ok`/`.badge.src-paper` (4.49) and for `.cite-dropped` (4.46, deliberately dimmed). Dark mode is ≥ 5.58 throughout.
- **N2 (polish):** LaTeX from papers is shown raw in answers, for example `$M_{sr}$` and `$s = [x, z_{1\dots i}]$`. This is readable but unrendered. Out of scope unless desired.
- **N3 (info):** the Routing tab shows the decision's `model_id` and "served by <upstream>", but not `model_returned`. They were equal on all 12 calls observed. Consider showing `model_returned` only when it differs.
- **N4 (info):** in a hidden tab, rendering waits for `requestAnimationFrame`, so the answer appears at the end. Normal browser behaviour, not a streaming defect.
- **N5 (latent):** an id containing `/` would 404, because `{chunk_id}` does not match `%2F` after decoding. No real id contains `/` today. If ids ever gain one, use a `{chunk_id:path}` route.
