## 4. Defects

### P4-D1: Major. Gemini cost estimate uses a price basis that the actual billing does not match
- **Reproduce.** Take any Gemini `llm_result` and compare `est_cost_usd` with `reported_cost_usd`.
  - Example: 357 input and 100 output tokens gave est **$0.000707** and reported **$0.0012855**.
  - Across **all 75 Gemini calls** with a reported cost (my runs plus `eval/results/phase4/*`), the reported cost equals in·$1.50 + out·$7.50 per 1M **exactly**.
- **Cause.** `policy.PRICES` uses the public OpenRouter catalog price, $0.825 / $4.125, which I confirmed today. These calls are BYOK (README §pricing), so the bill is Google's upstream charge, which OpenRouter reports as $1.50 / $7.50.
- **Effect.** Every Gemini `est_cost_usd` (in the UI Routing tab, `done.est_cost_usd`, README "typical question $0.02–0.03" and architecture §6 prices) understates real Gemini spend by about 45% (factor 0.55). The student's $1.50 Phase 4 budget tracking is understated as well. Any BYOK fee is unverified.
- **Not affected.** The routing decisions are not affected. Gemini is still cheaper than `gpt-6.1-sol` ($2 / $10), so the "cost" rationale stays truthful.
- **Expected.** Estimates should use the price actually billed, with a dated official source (Google Gemini API pricing for the upstream model), or should prefer `reported_cost_usd` when present and label which one is shown. Docs should state the BYOK basis.
- **Component:** `app/llm/policy.py` PRICES, README pricing table, architecture §6, `.env.example` comment.
- **Rubric impact:** evaluation cost reporting (Phase 9) and documentation truthfulness. It does not affect the routing criterion.

### Non-blocking notes
- **P4-N1 (Phase 7 scope).** Per-attempt LLM timeouts are not clamped to the remaining request budget. The `remaining_s() > 5` guard only gates starting a retry or fallback.
  - With real config, a synthesis that starts at t≈30 s and hangs can time out at 90 s, then retry until about 150 s. That is about 30 s past `REQUEST_BUDGET_S=120`. The worst-case overrun is about 55 s.
  - This is still bounded and below the Cloud Run 300 s limit. Reproduced at small scale in TC-P4-11.
- **P4-N2 (rubric risk, design).** Only the `synthesize` call site varies provider with features. Planner, tool-loop and worker_final are fixed to Gemini by call site.
  - This is legitimate hybrid routing by observable features, and the decision is agent-independent (TC-P4-03).
  - However, in practice every worker LLM call today lands on Gemini. When Summary and Data are added (Phases 5–6), consider at least one worker-side feature-dependent decision, so the "not a fixed provider per worker" argument does not rest only on synthesis. Document this in §6.
- **P4-N3.** The comparison cue misses non-lexical comparisons, for example "How does AutoGen stack up against CAMEL". Such a question still reaches capability when evidence spans 3 or more papers. This is a heuristic limit, worth one sentence in §6.
- **P4-N4 (test harness).** The live tests share langchain-openai's cached pooled httpx client across pytest event loops. The first request in a later test can fail with a stale connection, and the router retries it, so it is masked. This does not affect production, but live tests should run in one loop or reset clients, to avoid misleading `llm_retry` evidence.
- **P4-N5 (observation).** OpenAI synthesis for broad questions took up to 23.2 s (816 output tokens) against a 60 s total-stream timeout. A mid-stream timeout ends the request with an error rather than a fallback, as documented. Watch this in Phase 9.
- Markdown in answers renders as raw `**`/`$N$`. This is existing UI polish for Phase 8, not Phase 4.
