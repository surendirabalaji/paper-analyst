## 4. Defects

### P5-D1 (Medium; RAG 20% and frontend citations risk; blocks the Phase 5 P3-N3/P2-N8 scope)

**Off-topic answers can link unrelated corpus chunks as sources.**

- **Reproduction:** deployed D3, "At what temperature does water boil on the summit of Mount Everest?"
  - Research ran `corpus_search` and got off-topic chunks with best similarity 0.22.
  - It cited C1 and C6 in its findings to say the corpus lacks the data.
  - Synthesis wrote "The indexed arXiv papers do not contain … ; thus, all figures are provided from current web findings [C1], [C6], [W1]–[W7]."
  - `abstention_only_markers` splits at ";", so the marker clause has no abstention phrase. C1 and C6 got `citation` events and Sources entries.
- **Rate:** 1 of 3 Everest runs. A second run (D3p) had the same worker behaviour, but the backstop caught it. The local L1 answer shows the same pattern with on-topic chunks ("…still need verified external sources. [C1, C4]").
- **Expected:** a chunk is never presented as a source for a statement that the evidence is missing. Root-cause candidates:
  - Workers cite off-topic chunks.
  - The `needs_live` path skips the "do not cite off-topic passages" note, which is only injected when the low-support gate fires.
  - The backstop is phrase- and clause-dependent.
- **Repro tests:** TC-P5-01 (exact deployed sentence) and TC-P5-02 (graph path). Keep TC-P5-03 green.

### P5-D2 (Medium; regression from this phase; ops and Phase 7 diagnosability)

**`RedactingFilter` sets `record.args=None` on every record that has args, but uvicorn's `AccessFormatter` unpacks `record.args`.**

- **Effect on revision 00005:** every request logs "--- Logging error --- TypeError: cannot unpack non-iterable NoneType object" with a full stack. That is 48 tracebacks for 48 requests, and every access line is lost.
- Responses are unaffected, and the logged message is redacted.
- **Expected:** access lines format and stay redacted.
- **Repro test:** TC-P5-17.

### Non-blocking notes

- **P5-N1 (Low/Medium, watch in Phase 7):** Gemini via OpenRouter `empty_response` recurred on revision 00005, once in about 12 deployed requests (B1).
  - The new handling worked: it was traced as a fallback, and the request completed honestly as `partial`.
  - However, one empty reply moved all remaining calls in that request to OpenAI (8 OpenAI calls).
  - In that request Summary never invoked `tavily_search`, so sharing is not exercised on every natural question. D1 and B2 do show it.
  - B1 also sampled no incremental rendering. B2 rendered incrementally, and so did every API run.
  - I captured no SSE for B1, so the cause is undetermined.
- **P5-N2 (Low):** `status_cue` treats words like "citations", "current", "now" and any year 2025–2039 as status cues. A plain "Summarize X with citations" or "(2025)" task would enable `tavily_search`, which costs a credit and adds W# noise. Pinned by strict xfail TC-P5-05.
- **P5-N3 (Low):** the backstop unlinks supported negative claims, for example "Standard RAG cannot address noisy passages [C2]". Pinned by strict xfail TC-P5-04. Revisit together with the P5-D1 fix.
- **P5-N4 (Low, Phase 8):**
  - The W# viewer and trace show 280 characters, but the model saw up to 1,200. For example, D2's "91.69% … Lemon Agent [W5]" is not visible in the W5 viewer snippet, so a user cannot verify it without opening the page.
  - B1's W1 title was several titles run together, apparently as returned by Tavily.
- **P5-N5 (Low, quality):**
  - Summary's MetaGPT status query (a long quoted title plus "ICLR ACL") returned basketball pages (statmuse, sofascore, landofbasketball).
  - Summary listed W1–W4 in its `evidence_ids`. Synthesis correctly abstained on the venue, but the true status was missed.
