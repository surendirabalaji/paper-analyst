## 4. Defects

No core grading blockers.

- **P1-D1 (Medium) — `--limit` desynchronises SQLite from the index.**
  - Repro: build, then run `scripts/ingest.py --limit 1`. Test: `T1-CLI limit_does_not_desync` (xfail strict).
  - Expected: a testing subset run leaves `papers.db` consistent with the index (or does not write it).
  - Actual: `write_sqlite` rewrites `papers.db` with only the limited records, while pruning is skipped and the Chroma index keeps all 88 papers (DB {1 paper} vs index {3}).
  - Component: `scripts/ingest.py` (write_sqlite runs unconditionally; the manifest is correctly skipped under `--limit`).
  - Rubric impact: if run on the real data, the Data agent (Phase 6) and D# evidence would silently answer from a truncated DB. Fix: skip the DB write under `--limit`, or require a separate output path.
- **P1-D2 (Low) — duplicate seed id crashes late.**
  - Repro: seed with the same arxiv_id twice. Test: `T1-CLI duplicate_seed_id_handled` (xfail strict).
  - Actual: the Chroma sync completes, then `sqlite3.IntegrityError: UNIQUE constraint failed: papers.doc_id` is raised, and no manifest or DB is written. The existing DB survives because the write is atomic.
  - Expected: dedupe the seed, or reject it with a clear message before any writes. The current seed has no duplicates.
- **P1-D3 (Low) — some acknowledgments leak into chunks.**
  - `SKIP_TITLES` only matches an exact "Acknowledgments" heading. Two cases get through:
    - Headings with extra words, e.g. 2407.01502v1 `Sx1` "Acknowledgments and Disclosure of Funding".
    - Run-in "Acknowledgements." paragraphs folded into a conclusion: 2308.00352v7 S5, 2501.06322v1 S7, 2511.05385v2 S6, 2304.03442v2 S9.
  - Test: `T1-PARSE ack_variant_heading_dropped` (xfail strict).
  - Impact: minor retrieval noise. The docs claim that acknowledgments are dropped, which is not fully true.
- **P1-D4 (Low) — `EMBED_DIMS` is hard-coded to 1536.**
  - Changing `OPENAI_EMBEDDING_MODEL` to a model with different dimensions breaks in sequence: ingest first refuses with "re-run with --rebuild", then `--rebuild` drops the collection, records the new model with 1536 dims, and raises `embedding dims 3072 != 1536`. That leaves an empty, mislabelled collection. Test: `T1-CLI rebuild_with_wrong_dims_behavior` (asserts the current behaviour).
  - `query_index.py` checks only the model name, not the dimensions.
  - Fix: derive the dimensions from the model or config, or check them before dropping. This does not affect the selected model.
