## 4. Defects

**P8b-D1 (Minor, test harness; this resolves the known issue).** The developer's unit test `tests/unit/test_phase8b_latency.py::test_single_summary_task_seeds_outline_reads_sections_in_one_round` makes a real, paid OpenAI embedding call with the real key. This contradicts the file's "no network" claim. It makes the unit suite flaky (about 30 %, failure lands in a random later test).
- The integration failure in `test_phase6_live_data.py` has the same cause: an OpenAI async client from one anyio test loop is reused or closed after that loop is gone.
- Not a product defect: production runs a single loop, and rev-00016 logs are clean.
- Fix in tests only:
  - Give that unit test `speculative_retrieval=False`, or a retriever whose `search` is faked while `paper_chunks` stays real.
  - For live modules, use a module- or session-scoped `anyio_backend` fixture so all tests share one loop.
  - Do not turn speculation off in the product.

**P8b-D2 (Minor; pre-existing Phase 7 code, exposed by a real outage).** When an injected fault and a *real* failure happen in the same request, everything is labelled injected.
- Under `provider:gemini-openrouter:down` with OpenAI genuinely out of credits, `worker_result` had `injected: true` and `error_kind: rate_limit`. The rate limit came from the real OpenAI 429.
- The answer said "These failures were injected on purpose … they do not indicate a real outage", which is false.
- Expected: a real provider error stays unlabelled, and the advice names both causes.
- Repro (local, $0): set an invalid `OPENAI_API_KEY`, then send `X-Fault-Inject: provider:gemini-openrouter:down` with the token. Evidence: `deployed2/f_gemini_down_summary.run1.events.jsonl`.
- Rubric impact: small (truthful failure trace).

Notes (non-blocking):
- **N1:** `insufficient_quota` (429) is treated as transient `rate_limit`, so it gets one retry (0.6 s) before fallback. It is bounded, but quota exhaustion is not transient.
- **N2:** Research does not unlock `tavily_search` when `corpus_search` *errors*; the gate only opens on low support. During an embedding outage, in-scope questions therefore fail completely even though live web search works. This gate is pre-existing.
- **N3:** The plan note "planner-named paper not seeded (no indexed paper title contains 'HyDE'; it is not in the corpus)" appears as a warning, but HyDE *is* in the corpus (2212.10496), and the worker then found and cited it. The note should say "not resolved by that name".
