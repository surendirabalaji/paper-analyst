## 4. Defects

### P0-D1 (Medium): `phase0_check.py` reports Tavily `ok` with an invalid key
- **Repro:** `OPENAI_API_KEY=sk-CANARY… OPENROUTER_API_KEY=sk-or-CANARY… TAVILY_API_KEY=tvly-CANARYtavily0123456789 .venv/bin/python scripts/phase0_check.py`
- **Expected:** Tavily `status: error` (unauthorized).
- **Actual:** `status: ok`, `search_ok: true`, 282 chars, sample URL is Tavily's docs page. Tavily Remote MCP allows `list_tools` without a valid key and returns auth failures as a tool *result* (`{"error":"Search failed","status":401,…}`), not an exception; the script uses `search_ok = bool(text)`.
- **Impact:** Phase 0 evidence file cannot by itself distinguish real auth from failure. The exit criterion still holds through T0-TAV-STRICT (real results, no error key). This is a direct preview of a later rubric risk: if the Phase 5 MCP client uses the same success test, the Research/Summary workers would cite Tavily's error JSON as W# evidence and the trace would mark a failed live search as successful (affects Live retrieval, MCP-sharing 10%, and failure-handling honesty).
- **Fix direction:** parse the payload; treat `error`/`status>=400` or zero `results` as failure; record result count. `tests/integration/test_phase0_live_tavily.py` is the regression.

### Forward risks (not Phase 0 failures)
- **P0-R1 (Medium, Phase 2/4):** Gemini via OpenRouter spends ~450 reasoning tokens on a one-sentence answer and delivers content in 2–3 chunks after 5.4–5.6 s. If Gemini performs synthesis, browser streaming will look buffered (rubric "response delivered only after generation completes" partial-credit risk) and cost/TTFT rise. Control reasoning effort and re-measure chunk arrival in Phase 4.
- **P0-R2 (Low/Medium, Phase 4):** Gateway/provider interpretation. Catalog evidence shows Google upstreams only, but the script does not record the per-call upstream provider (OpenRouter `provider` field) or snapshot ID. Narrow ambiguity: whether "Gemini via OpenRouter" counts as a distinct provider is not ruled on by the PDF (its example lists Google/Gemini with a Google key). Record per-call origin, gateway, and returned model in routing traces.
- **P0-R3 (Low, Phase 5):** Tavily results returned `published_date: None` for general-topic searches; W# evidence will need retrieval timestamps from the app rather than relying on source dates.
- **P0-R4 (Low, Phase 1):** Ingest must check HTTP status (404 returns an HTML body), strip 9 nav/header/footer elements, handle unnumbered `Sx`/`Ax` sections, fix small-caps fragmentation, and confirm the in-page version matches the arXiv API version. A "200 but HTML conversion failed" page was not found/tested in this phase. Search result surfaced an arXiv blog post on an updated rate-limit policy (2026-10-01); check it before bulk fetching (treat as untrusted until read on arXiv's site).
- **P0-R5 (Low, Phase 9):** RAGAS 0.4.3 deprecates `ragas.metrics.ResponseRelevancy/LLMContextPrecisionWithReference/LLMContextRecall`; current names are `ragas.metrics.collections.AnswerRelevancy/ContextPrecisionWithReference/ContextRecall/Faithfulness`. dev_notes and compliance should name the API actually used.
