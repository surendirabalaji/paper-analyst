### P6-D1c: S3 Minor, not blocking: the temp-storage bound is per file, not per query

- **Input:** `WITH RECURSIVE r(n) AS (SELECT 1 UNION ALL SELECT n+1 FROM r WHERE n<1400) SELECT 1 FROM (SELECT s0 FROM (SELECT replace('xxxxxxxxxx'||<10,000-char replace chain>,'x','x')||n AS s0 FROM r WHERE n<=1400) GROUP BY s0) t0, … t7 LIMIT 1` (1,783 characters).
- **Expected:** total temp storage stays near the documented 16 MB.
- **Observed:** accepted, with a 200 MB peak (8 files of up to about 16 MB each), for 0.16 s. With concurrency 10 on a 2 GiB instance, about 10 such requests landing in the same sub-second window would be needed to threaten the instance. The tool-loop latency of about 10 s before `run_sql` makes this hard to time. The two-table form ran from the public URL.
- **Possible fixes (the developer chooses):**
  - in the child, set `PRAGMA temp_store=MEMORY` plus `PRAGMA hard_heap_limit=<e.g. 64 MB>` before installing the authorizer (process-wide is fine in a single-query child);
  - or lower `RLIMIT_FSIZE`;
  - or at least correct architecture §5, which currently implies temp storage is capped at 16 MB.
- **Rubric impact:** a small effect on deployment robustness only.

### P6-D3: S3 Minor, not blocking: an unusable database is reported as "simplify your query"

- **Input:** `run_readonly(Path('/nonexistent/x.db'), 'SELECT 1 FROM papers')`.
- **Expected:** an infrastructure or unavailable error that does not blame the query.
- **Observed:** `sql_rejected` "query exceeded the resource limits (memory, CPU or temporary storage); simplify it".
- **Cause:** `connect_ro` raises `OperationalError` outside the `try` in `_execute`. The child dies with a traceback, which is discarded because stderr is never logged, and the parent maps "no JSON" to a resource refusal.
- **Consequences:**
  - The model is told to "simplify" and spends its repair round.
  - Any unexpected child crash, for example an import error in the image, would look like a query problem with no log line.
- **Note:** a corrupt DB is still correctly reported as `sql_error` "file is not a database".
- **Possible fixes:**
  - map a non-zero exit with no JSON to a distinct kind (unavailable/internal);
  - log the child's stderr tail (redacted) and its return code;
  - catch connection errors inside `_execute`.
- **Regression test:** `test_T6_CHILD_MISSING_DB_is_not_a_resource_refusal`, a strict xfail. Remove the marker when this is fixed.
- **Rubric impact:** failure-handling truthfulness (Phase 7).
