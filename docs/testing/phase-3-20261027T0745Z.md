## 4. Defects and notes (none blocks the Phase 3 gate)

**P3-N1: Medium (security/deployment hygiene). API keys are stored as plaintext Cloud Run env vars and persisted in Cloud Audit Logs.**
- Repro: `gcloud logging read` for `cloudaudit.googleapis.com/system_event` `Services.CreateService` at 2026-10-27T07:22:55Z and 07:22:56Z. Fields `protoPayload.response.spec…containers[0].env[4|7|11].value` contain all three real keys (OpenAI, OpenRouter, Tavily). I matched them by value and never printed them. They are also readable through `gcloud run services describe`.
- Expected: credentials are not readable from service config or logs by project readers. Actual: anyone with logging or Run viewer rights on `changelens-510807` (a shared Assignment 1 project) can read them. System-event audit logs cannot be deleted.
- Not a public leak. Credentials are still externalized from the image and repo, and the README discloses the env-var visibility, but not the audit logs.
- Fix (needs student approval, since it enables an API and creates resources): use Secret Manager with `--set-secrets` (add `roles/secretmanager.secretAccessor` for the runtime SA). Rotate the three keys after migration if the project has other members. Update the README and `docs/dev_notes.md` ("deploy log contains no key values" is true for the script output only).

**P3-N2: Major carry-forward (orchestration/latency; affects "handles arbitrary reasonable queries"). The research worker runs close to `WORKER_TIMEOUT_S=45` on the deployed service.**
- Evidence: T3-19 worker span 43.6 s (its last tool-loop LLM call took 34.4 s writing a long draft), then 14.9 s of synthesis. TTFT 50.4 s.
- The main agent's earlier warm run of the same question (2 tasks) timed out twice and returned a partial answer after 97 s.
- I agree the root cause is not container-specific: the same call pattern shows locally (L1 research call 13.5 s, P2-N1), and Cloud Run CPU and memory are not limiting (memory about 25 %). But the deployed failure rate on broad questions is material.
- Fix in Phase 4/7: shorter worker drafts or structured evidence hand-off instead of a full prose draft that synthesis rewrites, budget-aware worker timeouts, and recording the partial-result rate. Retest with 2–3 broad multi-paper questions on the deployed URL.

**P3-N3: Minor (RAG citation quality). Abstention attaches unrelated citations.**
- Repro (T3-18): the AlphaFold 3 question returns "evidence does not answer this … [C1][C2][C9]", citing FireAct, Self-RAG and AI-Agents-That-Matter compute sections.
- These are retrieved and resolvable, but they support only "other papers were searched". CLAUDE.md says "never attach unrelated sources".
- Suggest that the synthesizer cites nothing when abstaining, or labels such sources as "searched, not relevant". Add a regression test asserting no citation events when the answer abstains. Phase 4/5.

**P3-N4: Minor (UX/scalability). Cold start is 17.9–34.4 s, and the user sees a blank page until the instance is ready.**
- The image is 1.86 GB locally (425 MB compressed). It includes ragas, datasets, pyarrow and scipy, which the runtime never imports.
- Index open is 4.6–7.4 s on 1 CPU vs 0.4 s locally.
- Options for later: a runtime-only requirements set, lazy heavy imports, or `min-instances=1` during the grading window (cost tradeoff, student decision). Phase 9 must report cold and warm separately (2 samples so far).

**P3-N5: Polish/observability.**
- (a) Worker timeouts and errors are not logged server-side. Cloud logs had zero warning/error lines for the earlier partial-failure request, and all app logs have blank severity. Add a structured warning log per worker error (Phase 7).
- (b) `app/main.py` comment says "send ours to stdout", but `logging.StreamHandler()` defaults to stderr. It works on Cloud Run either way; fix the comment or pass `sys.stdout`.
- (c) `/favicon.ico` returns 404 JSON.
- (d) `/docs` and `/openapi.json` are public (harmless; optional to disable).
- (e) The missing-credential startup error is a raw OpenAI traceback.

**P3-N6: Test hygiene (tester-side observation).** Opening the production index (the app, or pytest's real-index tests) appends Chroma bookkeeping to `data/chroma_index/chroma.sqlite3`, so its byte hash changes while the content stays the same. For provenance, record a logical hash (collection count plus segment-file hashes) rather than the sqlite byte hash. The full regression run here touched the file at 07:50Z; the content diff vs. the baked copy is only the `acquire_write` row.

**P3-N7: Evidence caveat for later phases.** In both paraphrase tests (HyDE, Gorilla), the LLM planner named the target paper from parametric knowledge ("Check Gorilla as a likely match"; "HyDE") before retrieval. So these end-to-end results do not isolate low-lexical-overlap vector retrieval. Phase 9 or the final audit should include retriever-level paraphrase checks, or papers newer than the model's knowledge (e.g., 2606.x).

## 5. Coverage gaps

- **Fresh-project deployment not executed.** It was deployed into an existing project with the APIs already enabled. In a new project, Cloud Build's default service account (commonly the Compute Engine default SA in newer projects) may need explicit IAM roles (Artifact Registry writer, logs writer, Storage object viewer for the staging bucket) or organization-policy changes. The README does not mention these. This is a final-audit obligation: try it in a scratch project if the student authorizes, or document the IAM prerequisites.
- Concurrency on the deployed service (concurrency=10, 1 CPU) is not tested in Phase 3. It is due in Phase 7/8.
- Deployed amd64 image contents were verified through the Cloud Build source archive and a local arm64 rebuild, not by pulling the deployed image. I avoided changing the local docker auth config.
- Routing (one provider only, "fixed default"), Tavily/MCP sharing, and the Data worker are future phases and correctly absent.
- The PDF was not re-opened for this phase run. Requirements were taken from CLAUDE.md, which is derived from it, and from earlier phase reports.
